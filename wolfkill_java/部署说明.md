# 狼人杀 · Java 联机版 部署说明

这是一个\*\*纯 Java（JDK 11+）\*\*实现的狼人杀多人联机服务端，**零第三方依赖**，前端 `index.html` 原样保留。  
适合部署在只有 Java 运行时的服务器（如雨云游戏云）。

---

## 一、目录结构

把你拿到的整个 `wolfkill_java/` 文件夹上传到服务器任意目录即可，目录下包含：

```
wolfkill_java/
├── WerewolfServer.java   # 服务端入口（HTTP 服务 + 路由 + 游戏主循环）
├── Room.java             # 房间状态、行动封装、夜晚/白天流程、狼队讨论、上警、平票二次投票
├── Game.java             # 游戏引擎：角色、状态、计票（1.5票权）、狼队平票随机
├── AI.java               # AI 决策（含调用大模型）；含 prompts.txt 加载
├── LLM.java              # OpenRouter 大模型客户端（含离线 mock）
├── Config.java           # 配置（模型、API Key、角色配比）
├── Json.java             # 极简 JSON 解析/序列化
├── prompts.txt           # 规则与角色攻略提示词（AI 系统提示词）
├── index.html            # 前端页面（玩家用浏览器打开）
├── start.sh              # 启动脚本（**前台常驻**运行，供云平台进程监控；切勿自行加 & / nohup）
├── stop.sh               # 本地停止脚本（pkill 方式）
├── *.class               # 已编译好的字节码（Java 11+ 通用，无需服务器装 JDK 也能跑）
└── 部署说明.md
```

> 说明：`.class` 文件是平台无关的字节码（已按 `--release 11` 编译），**只要服务器有 Java 11 及以上运行时（JRE 即可）就能直接运行**，不必安装 JDK。

---

## 二、运行方式

### 方式 A：直接运行（推荐，服务器有 Java 11+ 即可）

```bash
cd wolfkill_java
chmod +x start.sh stop.sh
./start.sh --port 3000
```

### 方式 B：服务器有 JDK，想自己重新编译

```bash
cd wolfkill_java
javac --release 11 *.java      # 生成 .class
java WerewolfServer --port 3000
```

### 启动参数

| 参数            | 说明                                          | 默认            |
| ------------- | ------------------------------------------- | ------------- |
| `--port 3000` | 监听端口                                        | 3000          |
| `--total 8`   | 一桌总人数（真人+AI），范围 4–12                        | 8             |
| `--mock`      | 离线模式：AI 用确定性逻辑，**不联网、不消耗额度**（适合先自测/无网络环境）   | 关             |
| `--model xxx` | 指定 OpenRouter 模型（默认 `nvidia/nemotron-3-super-120b-a12b:free`，免额度） | 见 Config.java |

---

### 配置大模型（真实对局，**无需改源码 / 无需重编译**）

服务端在启动时读取以下**环境变量**进行覆盖。这对只有 JRE、没有 JDK 的服务器尤其重要——  
你不必修改 `Config.java` 再编译，直接通过环境变量注入自己的 Key 即可：

| 环境变量                | 说明                                                   | 默认值                 |
| ------------------- | ---------------------------------------------------- | ------------------- |
| `WEREWOLF_API_KEY`  | OpenRouter API Key（真实对局必填；`--mock` 下可留空）             | `Config.java` 中的默认值 |
| `WEREWOLF_BASE_URL` | 兼容 OpenAI 格式的大模型接口地址                                 | OpenRouter          |
| `WEREWOLF_MODEL`    | 模型名（如 `nvidia/nemotron-3-super-120b-a12b:free`、`deepseek/deepseek-chat` 等） | `nvidia/nemotron-3-super-120b-a12b:free`  |
| `WEREWOLF_MOCK`     | 设为 `true`（或 `1`）强制离线，**不调用任何网络**                     | 关                   |

两种用法（任选其一）：

```bash
# 方式 1：先 export 再启动
export WEREWOLF_API_KEY=sk-or-你的Key
./start.sh --port 3000

# 方式 2：前缀式（单行生效，不污染当前 shell 环境）
WEREWOLF_API_KEY=sk-or-你的Key ./start.sh --port 3000

# 想临时用离线模式自测（覆盖 Config 里的默认）
WEREWOLF_MOCK=true ./start.sh --port 3000
```

> 提示：若不设置 `WEREWOLF_API_KEY` 又未加 `--mock`，真实对局会因鉴权失败（401）而报错；  
> 上线前请务必通过环境变量注入你自己的 Key。

停止（本地开发时）：

```bash
./stop.sh        # 或直接在运行 start.sh 的终端按 Ctrl+C
```

## 二之一、云平台报"实例启动后在极短的时间内退出"怎么办（重要）

### 现象
在雨云等游戏云 / 容器平台上填好启动命令、启动后，平台很快提示：
> 检测到实例启动后在极短的时间内退出，原因可能是您的启动命令错误或配置文件错误。

### 根因（与游戏代码无关）
这类平台的"进程管理器"会把**你填写的启动命令所对应的那个进程**当作要长期运行的服务来监控。
如果启动命令把 `java` 用 `nohup ... &` 丢到后台、脚本自己立刻 `exit`，平台看到"命令进程"瞬间结束，
就误判为"实例已退出"并报错——**实际上是 java 还在跑，只是平台盯错了进程。**

> 旧版 `start.sh` 就是 `nohup java ... &` 写法，会触发此问题。当前版本已修复为**前台 `exec`**。

### 正确做法
确保 `java` 是**前台常驻**的那个进程——本项目的 `start.sh` 已用 `exec java ...` 实现：
它把 shell 自身替换成 java 进程，于是 java 正好成为平台监控的长期进程。

**在平台的"启动命令"里填写（任选一种）：**

```bash
# 推荐：直接用脚本（内部已 exec 前台运行）
bash /你的路径/wolfkill_java/start.sh --port 3000

# 或者先 cd 再运行（确保工作目录是 wolfkill_java 文件夹）
cd /你的路径/wolfkill_java && bash start.sh --port 3000

# 真实对局（注入 Key，无需改源码）
WEREWOLF_API_KEY=sk-or-你的Key bash /你的路径/wolfkill_java/start.sh --port 3000
```

要点：
1. **不要**在启动命令里自己加 `&`、`nohup`、或用 `nohup ... &` 包一层——那会让脚本立刻退出。
2. **不要**把"启动命令"指向一个会 `exit` 的包装脚本；让最终进程就是 `java WerewolfServer`。
3. 平台若在"环境变量"一栏注入了 `PORT`，脚本会自动沿用（无需改 `--port`）。
4. 端口要与平台"对外/对内端口映射"一致；云主机还需在**安全组**放行该端口（见第四节）。

### 自检
启动后，若能在平台"日志/控制台"里看到如下横幅，说明前台运行正常、进程已常驻：

```
========================================================
🐺 狼人杀 · 多人联机服务（Java 版）已启动
========================================================
  本机访问：   http://127.0.0.1:3000
```

## 三、玩家如何加入

1. 房主在服务器上启动服务（绑定 `0.0.0.0`）。
2. 同一网络/通过端口映射能访问服务器的玩家，用**浏览器**打开：
   ```
   http://服务器IP:端口
   ```
   例如局域网：`http://192.168.1.10:3000`；外网：做端口映射后 `http://公网IP:端口`。
3. 输入昵称 → 进入房间（房主可调整人数并开始）。
4. 真人不够的席位由 AI 自动补位。

---

## 四、网络 / 防火墙

- 服务器若是云主机（如雨云游戏云），请在其**安全组 / 防火墙**中放行你选用的端口（如 3000）。
- 外网联机若 IP 不便直接暴露，可在本机用 `cloudflared` / `ngrok` 等内网穿透，把本地端口映射为公网地址后再分享给朋友。

---

## 五、功能对照（与原 Python 版一致）

- 核心玩法：夜晚（守卫→狼人→预言家→女巫→结算）、白天（发言→投票放逐）。
- 进阶：遗言（首晚被刀 / 被放逐时）、**上警竞选警长**（警长放逐投票计 1.5 票）、**平票二次投票**、狼队投票刀人（平票随机）。
- AI 调用大模型推理（含谨慎推理链、悍跳/对跳/归票/警徽流等进阶博弈）。
- 狼队密谋室：真人狼可与 AI 狼队友自由讨论后再拍板。
- 真人退出由 AI 接管，避免卡死。

> 安全提示：这是用于朋友间娱乐的轻量服务端，没有鉴权加固，请勿暴露到不可信的公网。
